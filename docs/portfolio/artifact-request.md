# Evidence request for public case studies

This checklist is intentionally specific. No artifact is required for areas that should remain generalized or private; only share material that is safe to publish or can be sanitized.

## 1. Production SaaS / inventory consistency

- Project or product description safe to name, or approval to keep it anonymous
- Exact personal contribution and dates
- Delivered components versus proposed/future components
- Sanitized architecture diagram, API outline, test output, or implementation notes
- Any outcome that is explicitly approved for publication
- Confidentiality restrictions

## 2. Backend reporting / reconciliation

- Project name or anonymous label
- Data sources and reporting/reconciliation workflow
- Exact ownership: schema, APIs, jobs, queries, dashboards, or operator tooling
- Verification artifact such as tests, sample sanitized output, or runbook excerpt
- Safe description of failure handling and freshness guarantees

## 3. AI document retrieval / knowledge systems

- Project and delivery status
- Exact contribution across ingestion, extraction, chunking, indexing, retrieval, prompting, evaluation or UI
- Approved technology list for that project
- Sanitized example, public demo, repository, test/evaluation record, or architecture diagram
- Any measured result only if directly supported and approved
- Confidential data or client-name restrictions

## 4. Real-time communications / streaming

- Product and feature scope
- Exact protocol/provider and personal contribution
- Connection, retry, ordering, backpressure or failure behavior that may be disclosed
- Test, demo, repository, or sanitized design evidence
- Delivered versus investigated/proposed status

## 5. AI voice integrations

- Specific integration and whether it shipped
- Personal contribution to audio, call/session, tool/action, transcript or handoff workflow
- Provider/technology details safe to publish
- Verification artifact and failure handling
- Approval for any client, product, volume or outcome wording

## 6. Independent client SaaS delivery

- Anonymous or named project label with client approval
- Engagement scope, dates and exact responsibility
- Architecture and delivery boundary
- Public demo, repository, screenshot, testimonial, handover artifact, or other safe proof
- Outcome evidence, if any
- Confidentiality and attribution limits

## Minimum acceptable evidence

An attributable public case study needs at least: a reviewed project description, exact contribution, delivered status, a safe technical artifact or independently checkable link, and confidentiality approval. A resume statement alone remains `reported`; it does not become `verified` without supporting evidence.
